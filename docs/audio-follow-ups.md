# Отложенные задачи по аудио и медиаресурсам

| Тема | Что проверить или спроектировать |
| --- | --- |
| Готовность медиа | Смена источника во время подготовки, `srcset`, исключения из подготовки и поздние события после смены посещения |
| Браузеры и транспорт | Проверка на реальных устройствах iOS и дальнейшие проверки приостановки и возобновления звука на разных платформах |
| HTML5 Audio | Оценить возможность удаления резервного транспорта после проверки поддержки Web Audio |
| Видео | Исследовать усиление дорожек видео с учётом CORS и жизненного цикла DOM-элемента |
| Стабильность браузерных тестов | Воспроизвести расхождение дробных координат выделения в проверке геометрии редактора |

## Завершено

- Относительная громкость аудио от 0 до 200%, усиление Web Audio и управление громкостью во время воспроизведения. [Адаптер Howler и измерения](audio-amplification-research.md)

- `onPause` и `onStop` привязаны к завершению логической команды. Нативные события Howler по-прежнему приходят отдельно по каждому голосу. Контракт отмены, выгрузки и Promise описан в [руководстве по аудио](book-audio.md).
- Проверка ускоренного ухода измеряет RMS в окнах, заданных по аудиочасам, и отдельно проверяет освобождение экземпляра. Под нагрузкой прежний таймер замера 35 мс срабатывал после окончания fade. Логический дедлайн проверяется управляемыми часами в Jest.
- Исправлен запуск в WebKit при исходном состоянии Howler `interrupted`. После браузерного разрешения Web Audio мог уже работать, а старт Howler оставался в очереди. Исправление использует штатную ветку Howler для `suspended`.
